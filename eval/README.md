# 召回评估集（recall set）

先造尺子，再造轮子：所有召回改进必须用这把尺子量出数字，不许"我感觉更好了"。

## 设计

- 54 条查询，三种类型，专门暴露不同短板：
  - **keyword（20 条）**：题面原词片段——字面匹配的主场
  - **paraphrase（18 条）**：换个说法问同一件事——考语义鸿沟
  - **scenario（16 条）**：面试现场转述（"面试官问我……"）——考自然语言鲁棒性
- 标准答案 = 题目标题；`expect` 可多值，命中其一即算中
- 来源：人工从 807 题库抽样手写（v1；LLM 批量生成 + 人工审是 v2）

## 指标

**recall@k** = 前 k 个结果里命中标准答案的比例。k=5：只塞 top-5 给模型，第 6 名以后等于不存在。

跑法：`python -m offer_coach.cli eval`（纯本地检索，零模型调用、零成本）

## 基线（2026-10-14，纯 FTS5 trigram，整句短语匹配）

| 类型 | recall@5 |
|---|---|
| keyword | 100%（20/20） |
| paraphrase | 0%（0/18） |
| scenario | 0%（0/16） |
| **总计** | **37.0%（20/54）** |

34 条漏网清一色"无结果"：整句被当一个短语做连续匹配，一个 trigram 对不上就空手而归。

## D14 消融设计（`ablate` 命令）

- **埋雷稿 v3（2026-10-18，提高考试难度）**：6 份（t01-t06），每份 8 个问答、约 800 字；
  只有第 3、5 题附近埋 2 颗"半对半错"的雷，其余 6 题回答正确作为干扰。
  例如"余弦不受长度影响，所以点积也不受影响"——前句正确、后句错误，
  考的是能否识别局部错误，不再是一眼假的错误观点
- **三配置对照**：full（完整版）/ no-kb（没收题库工具，剧本同步改两步）/ no-script（摘掉导演剧本只留身份）
- **每配置每稿跑 2 遍**（共 36 次诊断 + 36 次判卷）：报均值 ± 标准差，方差是诚实的一部分
- **判定口径 v2（LLM 裁判）**：每颗雷带标准答案（wrong=错误说法 / correct=正确说法），
  裁判判两条件——① 报告明确指出该说法是错的 ② 给出正确方向。命中必须带报告原话证据；
  判不出来一律算不中（fail-closed）。裁判与考生同模型（DeepSeek）是已知局限，
  三配置同一裁判，相对比较公平
- 跑法：`python -m offer_coach.cli ablate`（真调 DeepSeek，诊断与判卷都会计费）

### 仪器迭代记录

  416 请求，$0.6649。full 的 8 次翻车 = 5 stuck + 3 max_iterations，
  集中在 t02-t05；唯一一次有效但漏雷经人工解剖是裁判假阴性
  （报告附录实际已指出错误并给出正确方向），官方数字不改、局限如实记录。
  已补失败工具轨迹（工具名+截断参数）。消融实验已停止，不再继续投入 API 调用；

## D13 结果（混合召回，`--mode hybrid`）

| 类型 | 基线（phrase） | D12（terms） | D13（hybrid） |
|---|---|---|---|
| keyword | 100% | 100% | 100% |
| paraphrase | 0% | 33.3% | **55.6%** |
| scenario | 0% | 81.2% | 81.2% |
| **总计** | **37.0%** | **72.2%** | **79.6%** |

机制：字面通道（D12 拆词）+ 语义通道（本地向量）各查各的，**RRF 按名次融合**
（每题得分 = Σ 1/(60+名次)）——两路分数是两种货币没法比大小，但名次可比。
向量后端：fastembed + bge-small-zh（512 维，本地离线，807 题坐标入库一次性算好）；
Embedder 接口可换 API 实现（D010：DeepSeek/Kimi 均无 embedding 接口，故本地为默认）。
scenario 持平说明这类查询的字面重叠本来就够（拆词已解决）；paraphrase +22pp
才是语义通道的真正战果——字面零重叠的题，坐标近也能找到。

插曲（面试素材）：HuggingFace 直连被墙 → `HF_ENDPOINT=https://hf-mirror.com`
镜像 16 秒下载完——D010 的风险备案精准命中。

剩余 11 条漏网（8 转述 + 3 场景）：语义鸿沟最深区，bge-small 512 维拉不动
（如"插件和函数调用有什么区别" vs "Skills 是什么？"——需要模型真懂概念层级）。
v2 方向：更大模型（bge-m3）/ 加 reranker / 题库侧补同义词。

## D12 结果（拆词 OR 预处理，`--mode terms`）

| 类型 | 基线（phrase） | D12（terms） |
|---|---|---|
| keyword | 100% | 100% |
| paraphrase | 0% | 33.3% |
| scenario | 0% | 81.2% |
| **总计** | **37.0%** | **72.2%** |

机制：三刀拆词（标点切段 → 停词当刀 → 长段滑窗二字块）→ 每词各查一遍 →
加权合并（标题命中 2 分 / 正文 1 分，同分比最佳名次，每词 limit×4 进合并池）。
检索引擎一行没改，只加前置工序（`knowledge/preprocess.py` + `search_smart`）。

中途插曲（面试素材）：第一版按"命中词数"排序导致 keyword 回退到 95%——
高频词"工具"的 LIKE 池按写入顺序返回前 5 条，目标题没进池。
修复 = 合并池放大到 limit×4 + 标题加权。教训：**拆词解决"查不到"，引入"排不准"；
排名质量的债归 D13 重排管**。

剩余 15 条漏网全是真·语义鸿沟（如"插件和函数调用有什么区别" vs 标准题
"Skills 是什么？为什么有了 MCP 和 Function Calling，还需要 Skills？"）——
字面零重叠，拆词救不了，归 D13 向量召回。
