面试官：先自我介绍一下，然后说说你最近做的这个面试诊断 Agent 项目吧。

候选人：我是 28 届的应届生，主要做 AI Agent 方向。这个项目叫 offer-coach，输入是面试问答的文字稿，输出是结构化的诊断报告，告诉你哪些知识点薄弱、该怎么补。架构是我手写的 Harness，没有用 LangChain，因为我想搞清楚每一层的原理，不想只会调框架。

面试官：不用框架的话，你的 Agent 主循环是怎么实现的？

候选人：就是一个 while 循环。每轮把对话历史发给模型，模型要么直接回复文本，要么下单要调工具。如果下单工具，我就执行工具，把结果拼回历史，再进下一轮。直到模型不再下单、输出最终回答，循环就结束。中间有防死循环的机制，比如同一工具同样参数连续调三次就判定卡死，直接让它基于已有材料收尾。

面试官：工具调用失败了你怎么处理？

候选人：失败不会让程序崩掉。所有工具执行的异常都会被抓住，变成一段错误文本喂回给模型，让模型自己决定是换个参数重试还是放弃这条路。另外我给工具调用加了预算，总工具最多 8 次，知识库检索最多 3 次，超了就补一条回执告诉模型预算用完了，让它用已有的东西收尾。这样长稿子也不会无限烧钱。

面试官：你提到知识库检索，你的题库检索是怎么做的？

候选人：最早用的是 SQLite 的 FTS5 全文检索，trigram 分词解决中文没空格的问题。但纯字面匹配换个说法就查不到了，比如人家问"换个问法"，字面零重叠就傻眼。所以后来加了向量通道，用本地的 bge-small 模型把 807 道题都算成坐标存进库里，查询来了两路各查各的。

面试官：两路结果怎么合并？向量分数和字面分数能直接比吗？

候选人：不能直接比，两路分数是两种货币，量纲完全不一样。我用的是 RRF，倒数排名融合，不看分数看名次：每道题的得分是所有通道里 1 除以（60 加名次）的求和。一道题在两个榜都出现就拿双份分，自然浮到前面。这个 60 是平滑常数，防止第一名和第二名差距过大。

面试官：RRF 之后就是你最终的检索结果了？

候选人：不是，后面还加了一级精排。RRF 用的是名次，是二手信息，名次本身可能被字面噪音污染。所以我加了个 cross-encoder 的 reranker 模型，把查询和题目原文拼在一起逐对精读打分，相当于粗排海选进前 30，裁判复评后再发奖。裁判是本地模型，不花 API 的钱。

面试官：那这个 reranker 相当于给向量通道加权吗？

候选人：对，差不多就是加权，就是把向量那边的权重调高一点，让语义相近的排前面。

面试官：你刚才说向量模型是 bge-small，为什么不用更大的模型，比如 bge-m3？

候选人：呃，主要是 bge-small 比较小，下载快。大模型效果应该会好一点，但我觉得检索不准更多是别的问题，就先没换。

面试官：换个话题。你的对话历史越来越长怎么办？context 会爆的。

候选人：我做了两层。system 提示词和第一条用户消息是死保区，永远不动；中间的对话是滑窗区，超预算了就从最老的开始扔。扔的时候工具调用和它的回执是成对扔的，不能留一个孤儿调用在那里，不然模型API会报错。token 数是中文字符按一个 token 估算的。

面试官：一直扔的话，早期的关键信息不就丢了？没有别的办法吗？

候选人：还可以做摘要压缩，就是把老对话让模型总结成一段摘要再放进去。但我没做，因为我这个诊断流程一次就四五轮，离窗口上限远得很，摘要是又花钱又可能出错的东西，等真需要再加。

面试官：你的系统里有没有记忆？比如同一个候选人第二次来诊断。

候选人：有的。每次诊断完，如果分析里某个维度打分低于 3 分，就记一条弱点到 SQLite 里，同一个弱点重复出现就加坐实度，封顶 1.0。下次开局的时候把这个人的历史画像、坐实度高的弱点、最近两次诊断摘要拼进提示词里。写入只用死规则，不让模型自己判断"这值不值得记"，因为模型判断容易什么都往里记，最后变成垃圾桶。

面试官：那如果候选人进步了，弱点怎么洗掉？

候选人：现在不洗，只坐实不洗白。……因为洗白规则比较麻烦，要定扣多少、什么时候算洗白，我就先简化掉了。这个确实是 TODO。

面试官：行。我问几个基础点的。RAG 的文档切块一般怎么切？

候选人：常见三种吧。固定长度切，简单粗暴但容易切断句子；按结构切，比如按标题、段落；语义切，用向量判断哪里是话题断点。我自己项目里题库是 markdown，直接按标题结构切的。

面试官：向量检索里算相似度，余弦相似度和点积有什么区别？

候选人：余弦会把向量归一化，只看方向不看长度；点积会受长度影响。……不过我记得余弦在向量特别长的时候也会受长度影响，因为它俩本质上差不多。

面试官：嗯。如果用户上传的是面试录音而不是文字稿呢？

候选人：我现在的版本只做文字稿。但架构上留了门：输入层可以做一个统一的分轮结构，ASR 转写只是一个输入适配器，转完变成"谁说、说了什么"的结构喂给下游，诊断逻辑一行都不用改。做不做语音识别本身不是重点，复盘质量才是。

面试官：最后问个工程问题。你怎么证明你加的每一层机制是有用的？

候选人：我建了一个 54 条的人工评估集，分三类查询：原词、转述、面试现场复述，每条有标准答案，算 recall@5，就是前 5 个结果里有没有标准答案。每次改检索都跑一遍这个尺子，从最早的 37% 一路改到 92.6%，每一步涨不涨、涨多少都是数字说话。不达标就回滚，不凭感觉。

面试官：92.6% 之后剩下的漏网之鱼是什么情况？

候选人：剩 4 条，都是召回病，就是目标题连粗排前 30 都没进，裁判看不到它，再强的复评也救不了。药方是同义词扩展或者题库侧补内容，但边际收益已经很低了，我就没继续投入。

面试官：好，今天就到这里，等通知吧。

候选人：好的，谢谢面试官。
