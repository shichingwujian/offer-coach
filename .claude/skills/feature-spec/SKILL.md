# feature-spec：业务语言 → 技术方案翻译器

用户的痛点是"只会业务语言，不懂技术细节"。本 skill 的核心职责是翻译 + 教学，不是直接写代码。

## 触发

用户描述了一个新功能、新能力或修改（例如"加收藏，按收藏时间倒序"）。

## 流程

1. **复述需求**：用一句业务语言复述，确认理解无偏差。有歧义就列出歧义点让用户选。
2. **前置知识讲解（铁律：没教过的不许考）**：方案涉及而用户尚未接触的概念，先用大白话 + 类比 + 锚定用户已懂的代码讲透，再进入方案。例如讲 Query Engine 前，先用 agent-api-lab 讲"接口=插座"。
3. **翻译成技术方案**，固定分四层写：
   - 数据模型：动哪些表/Pydantic 模型，字段是什么，为什么
   - 检索/逻辑：核心流程怎么走，用大白话 + 关键代码位置
   - 接口：动哪些 CLI 命令 / 未来 API，输入输出长什么样
   - 测试：哪些行为必须有测试锁定（用"输入 X 应输出 Y"描述，不写代码）
4. **解释影响面**：这个改动会碰到哪些已有模块，会不会破坏已有行为，参考了 OfferPilot/教程的哪个设计（查 CLAUDE.md 参考实现地图）。
5. **三个为什么考试**：只考第 2 步讲过的内容。出 3 个"为什么"问题，例如"为什么这个字段放这张表而不是那张？""如果不用 FTS5 会怎样？"。用户答对（或 AI 讲解后用户能复述对）才进入下一步。**考试不通过禁止写代码。**
6. **确认后实现**：按方案实现，遵守 CLAUDE.md 开发约定。
7. **范读**：实现完成后，给用户一份"代码导读"——按什么顺序读、每个文件的核心是哪几行、和已学概念怎么对应。用户带着导读读，不是裸读。
8. **收尾**：更新 progress.md；方案里的关键取舍写进 decisions.md。
