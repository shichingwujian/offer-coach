# 12 | P0-2 工具调用预算：先补回执，再无工具收尾

> P0-2 学习笔记（含 explain-back 问答记录）。代码在 `src/offer_coach/tools/loop.py` 和 `skills/diagnose.py`，131 个离线测试全过；未调用真实 API。

## 一句话本质

工具预算统计的是模型**下了多少张订单**，不是工具成功了多少次；预算耗尽后先给每张未执行订单补 `tool` 回执，再发起一轮不提供工具菜单的 `finalize` 收尾调用。

## 架构示意图

```text
模型声明工具
  ↓
重复检测（同一动作第 3 次仍优先 stuck）
  ↓
预算检查（总预算 / 单项工具预算）
  ├─ 未超预算 → execute_tool → tool 回执 → 下一轮
  └─ 超预算
       ↓
   ToolTrace: budget_exceeded
   history: 补 tool 回执（保证订单/回执成对）
       ↓
   finalize 轮：engine.query(..., tools=[])
       ├─ 直接回答 → completed
       └─ 仍下单 → tool_budget_exceeded（同样补回执）
```

`max_iterations` 管正常工具循环；`finalize` 是预算耗尽后的额外一次无工具收尾，因此收尾成功时 `iterations` 可能是 `max_iterations + 1`。

## 两条预算的分工

- **总工具预算**：防模型在不同工具或不同参数之间来回跳。
- **单项工具预算**：防模型反复调用同一个高成本工具，例如 `query_knowledge_base`。

正式诊断默认：总工具 8 次，知识库检索 3 次。正常三步流程只用 3 次，预算是安全闸，不是新流程。

## 三个为什么（验收问答记录）

### Q1：为什么预算统计“模型声明了多少次工具”，而不是工具成功了多少次？

用户答：如果只统计成功，错误调用会一直跑。补充完整：成功、报错、空结果、权限拦截都可能让模型继续循环；只算成功就给了失控路径绕过预算的后门。预算是 Harness 的安全闸，必须按“声明次数”计数。

### Q2：为什么超预算后必须补一张 tool 回执？

用户答：tool 要有对应的 id 回收。补充精确说法：assistant 消息里的每个 `tool_call.id` 都需要一条同 id 的 `role="tool"` 消息配对；否则下一轮历史和存档续跑会出现“有订单、没回执”，真实 API 也可能拒绝这段历史。

### Q3：为什么总预算和单项预算要分开？

用户答：可能会超预算，所以分开计算。补充完整：总预算是防火总闸，管所有工具的组合失控；单项预算是局部水阀，专门管某个工具的反复调用，例如长稿里反复查知识库。

## explain-back 补充

用户复述了正确顺序：重复检测 → 预算检查 → 未超预算执行 → 超预算记录 `budget_exceeded` 并补 tool 回执。最终补齐最后一步：补回执后进入无工具 `finalize` 轮，直接回答为 `completed`，继续下单为 `tool_budget_exceeded`。
