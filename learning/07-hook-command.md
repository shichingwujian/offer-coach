# 07 | Hook + Command 层：插线板与直达电梯

> D9 学习笔记（讲解版——explain-back #8 跳过，用户拍板）。代码在 `src/offer_coach/hooks/`，57 个测试全过。

## 一句话本质

治理功能（权限/审计/压缩/记忆）如果不做成插件，每加一个都要打开 loop 的身体塞代码。插线板 = pre/post 两排插孔，**loop 从此对修改关闭、对扩展开放**——注册表原则（D4）的第三次兑现。

## 核心概念（大白话版）

- **pre 孔 = 开火前检查**：厨师点火前查"你有没有权利用这个灶"——没通过就不许开火，菜根本不做。**权限闸必须插这里**；插 post 孔 = 菜炒完了才说他没资格进厨房（危险已发生，马后炮）
- **post 孔 = 出锅后装盘**：菜已经做好了，端上桌前修整——`truncate_hook` 把 8000 字的高手答剪到 2000 字，防桌面爆炸（D7 预算）
- **短路（run_pre）= 一票否决**：安检第一道查出打火机，后面不用查了。代码：`if not allowed: return`，后面的插件根本没机会跑
- **逐级改写（run_post）= 流水线加工**：包裹过流水线，每个工位在上一棒基础上继续加工。代码：`result = hook(..., result)`——每个插件的输出是下一个的输入
- **为什么不能反过来**：pre 只产出"放行/拦截"的判断，没有"结果"可逐级传；post 若短路，第一个插件改完后面就没机会了
- **as_hook() = 转换插头（适配器）**：闸门的 `check()` 是老国标插头，插线板只认新接口，`as_hook()` 包一层做翻译——D8 的闸门逻辑**一行没改**
- **斜杠命令 = 直达电梯**：`/cost` 查的是自己账本，代码一行搞定。让模型查账 = 花钱雇人打电话问电厂，还可能听错（token 成本 + 延迟 + 幻觉风险）
