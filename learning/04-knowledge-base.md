# 04 | 题库层：进货、上架、查索引页

> D5 学习笔记。代码在 `src/offer_coach/knowledge/`，30 个测试全过，实灌 807 题。

## 一句话本质

把 807 道面试题从 markdown 搬进 SQLite，印好索引页（FTS5 倒排索引），让模型下单查题时**翻索引页**而不是**逐页翻书**。

## 一道题的旅行（四站）

```text
markdown 文件（17 个分类目录）
  →【parser.py 拆箱员】正则认题头（## Q / ### Q 两种都算），切块成 Question
  →【db.py build_db】进货上架：删旧库 → 建 FTS5 表（trigram）→ 逐题写入（幂等）
  →【db.py search_questions】检索：≥3 字 MATCH 翻索引；<3 字 LIKE 兜底
  →【builtin.py make_query_knowledge_base】工具换内脏，说明书不变，模型无感
```

## 核心概念（我的大白话版）

- **倒排索引** = 书末索引页："词 → 哪些页"。LIKE 是逐页翻书（全表扫描），MATCH 是查索引页
- **trigram** = 3 字滑窗切词，解决中文没空格的问题。**索引页上全是 3 字条目，所以 2 字词（"记忆"）翻不了索引页**，只能 LIKE 兜底（书薄，翻全书也就一瞬）
- **灌库** = 进货上架，一次性慢活；检索 = 查索引，高频快活。分开是因为：慢活干一次，快活干万次；且索引页只有上架时才印得出来
- **幂等** = 跑两遍结果一样。先删旧库再建新库，防 807→1614 双胞胎
- **rank** = 相关度排队：标题命中的排前面，LIKE 给不了

## 工厂函数第二次出现

`make_query_knowledge_base(db_path)` 和 `make_analyze_content(engine)` 同一手法（闭包）。**两件行李的共同点：都是模型填不出来的东西**——模型下单只能写 JSON 文本，填得出关键词，填不出 engine 对象和 db_path 这种程序配置。凡是模型填不了、函数干活又必需的，装配时焊进去。

## 我栽过/问过的地方

- 第一次实灌只有 369 题：题库 `## Q：` 和 `### Q：` 两种标题混用，解析器只认了一种 → 修正则后 807 题全收
- "记忆"搜出 0 条：trigram 不收 2 字词 → 加 LIKE 兜底。**两个 bug 都是实灌真数据逼出来的，测试数据太干净发现不了**
- trigram 的 3 字是焊死的改不了；想正经支持 2 字词得用 jieba 分词后加空格再入库（backlog 扩展点）
