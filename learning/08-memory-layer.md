# 08 | Memory 层：跨会话记忆的档案柜

> D10 学习笔记（讲解版 + 考试记录：坐实机制复述通过）。代码在 `src/offer_coach/memory/`，75 个测试全过。

## 一句话本质

Context（D7）管"这次对话看什么"（桌面），Memory 管"跨对话记什么"（档案柜）。模型是金鱼，档案柜让它"记得"这个人上周 Redis 答得稀烂。

## 两把尺子（本层心脏，别混）

| | 分数 score | 坐实度 confidence |
|---|---|---|
| 量什么 | 这一次**每个维度**的表现（4 个分） | 这条弱点记忆有多可信 |
| 范围 | 1–5 | 0.0–1.0 |
| 谁打的 | 模型（analyze_content） | 档案柜自己算 |
| 管什么 | **记不记**（<3 才记档） | **取不取**（≥0.6 才上桌） |

## 坐实机制（考试错了又补会的点）

同维度考砸**不新增条目**，坐实度 +0.1（封顶 1.0）：一次考砸是意外（0.5 观望不上桌），次次考砸才是弱项（0.6 上桌）。**次数不记在条数上，记在坐实度上**——三条一样的记录是垃圾重复。排序坐实度优先、时间其次。

召回 = 每次开局从柜子抽几份相关档案摆上桌（拼进 system prompt），模型开局就看到历史。

## 写入克制（死规则，不让模型自由发挥）

- 只有 analyze_content 触发；只记 <3 分；解析不到宁可不记
- 不记：全文、中间推理、工具原始输出、能从题库重查的东西
- preference 类型不做：要模型判断"值不值得记" = 垃圾桶风险（教程点名）
- /profile 手动写画像：直达电梯式死规则

## 插件新类型：旁观型

post 孔两种用法：改写型（truncate 装盘，动包裹）vs 旁观型（档案员 = 流水线上方的扫码摄像头，只看不动）。**插件顺序有意义**：档案员在前看原文，truncate 殿后改副本。**跑成才记档**（completed 之后才 _write_summary）。

## 副作用升级：analyze v2 结构化

自由文本 → JSON 评分 + 确定性渲染（排版不烧钱）+ 原文兜底（失败当数据）。分数程序可读 → 记忆层和评估集都能消费。

## 我的 Q3 想法（v2 扩展点，面试可聊）

答对多次触发洗白（连续 2 次 ≥4 分降坐实度）；洗白后不删，标"已攻克"留档 = 进步轨迹。**题库装知识本身，记忆库装关于人的事实**——两个柜子别混。

## 埋给冲刺的钩子

记忆检索现在只有 SQL 条件过滤；混合召回冲刺时记忆和题库一起升级向量检索。
